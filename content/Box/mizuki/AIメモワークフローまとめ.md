# AIメモワークフローまとめ（2026-08-06〜07 議論）

かえでちゃんとミズキの2日間にわたる議論のまとめ。目的は「AI時代のメモの取り方」を設計すること。

## 目的

**アブダクション推論（ひらめき・アイデア）を最大化するためのメモシステム**。
演繹・帰納はAIに任せ、人間はアブダクションに集中する。

関連: [[アブダクション]] / [[アブダクション推論が起こるパターン]] / [[演繹推論によって論理知は増えない]] / [[知的生産とはなんなのか….]]

## 原則

> **書くのは人間、読む・整理する・出会わせるのはAI**

## ワークフロー5層

| 層 | 誰が | 内容 |
|---|---|---|
| ① キャプチャ | 人間 | おもしろいと思ったことを1行でサクッと書く。形式自由（テキスト・音声・ウォッチ1タップ） |
| ② コンテキスト | 人間+自動 | 後から詳細を追記。スクショ・位置・時間は自動取得。AIの拡大解釈を防ぐ |
| ③ 整理 | AI | タグ付け・要約・関連付け。「AI」マーク付きの提案として表示。生メモは不変 |
| ④ 出会い | アルゴリズム+AI | 忘却バイアス付き再提示（クーリングオフ+重み付きランダム+反応フィードバック） |
| ⑤ リンク生成 | AI | ベクターDBで類似関係を発見 → 人間可読な`[[Wikiリンク]]`を生成（提案ベース・3〜5本に絞る） |

関連: [[メモは知的生産のどの部分に寄与するのか]] / [[メモは推論のどの部分に寄与するのか]] / [[メモを検索できるようにする]]

## アブダクション4条件との対応

- **アノマリー** → AIが新メモと過去メモの矛盾・ズレを検出
- **多様なインプット** → 大量メモの圧縮 → 「関心の地図」として提示
- **出会い** → ランダムペア・FSRS的な再会・意味的に遠い2つの提示
- **操作** → メモのシャッフル・再構成ドラフト

## 技術基盤

- データ: Markdown vault（ポータビリティ）+ 3層構造
- 同期: rclone（フォルダ分け運用: 人間専用/ミズキ専用/共有）
- 高速検索: FTS5（キーワード）。ベクターDBは意味検索・RAG・出会いの場のため
- ベクター化: BGE-M3等のローカル埋め込み + sqlite-vec
- AI整理: BYOK（ユーザーがAPIキーを入れる）。ローカルLLMは再現性の観点で不採用
- 連携: MCP/API基盤

関連: [[ツェッテルカステンにMarkdownはいらない]] / [[ツェッテルカステンにmarkdownは必要]] / [[ツェッテルカステンとLLMが相性が悪いのは、効率が悪いから。]]

## 運用ルール

1. 生メモ（Layer 0）はタイムスタンプ付きで不変
2. AIの出力は常に提案。人間が確定する
3. メモをきれいに整える作業は一切しない
4. ツェッテルカステンの3ステップ（書く→収納→整理）を人間とAIで再配分したもの

## 最近の論点（検討中）

### 思考の過程（Layer S）
- 思考メモは「記録」ではなく「考えるための道具」
- 作業領域として扱い、保存義務なし。期限付きアーカイブでも可
- AIが消化して結論・仮説・疑問・アクションを抽出 → 正式メモに昇格

### 介入レベル（かえでちゃんが検討中）
- **聖域**: AIが一切触らない（読むのも禁止）
- **人間主導**: AIは読めるだけ。整理・提案・書き込みなし ←「私が書いて、私が読む」領域
- **AI協働**: 5層ワークフローの対象
